- `body` (island `v0.2.3-cc25`; a host gates it on `ev.ready` `caps` listing `placeBody`, below; an older island answers `bad_args` to it): a self contained `kicad_symbol_lib` text of 1 byte to 4 MiB (4,194,304 bytes as UTF-8), the symbol `name` in it with any `extends` chain inside it. The item is built from `body` and placed as `lib:name`, never read from `lib.item` or a library file: `lib` needs no symbol file and no row behind it (a design's HTTP source row, or no row at all), and its definition is cached in the sheet's `lib_symbols` as for any `place`. Everything else is `place` as above: `kind` must be `"symbol"`, `lib` holds no colon, `value`, `footprint`, `mpn` and `manufacturer` are written on the instance, one item at a time, Escape drops it, a press commits it as one undo step. The checks, in order: the args (`bad_args`: a body that is not a string, empty, over the bound, not a `kicad_symbol_lib`, unbalanced or naming a parent it does not hold, a `footprint` kind, a colon in `lib`); the frame (`unsupported` outside a `sch` frame); the engine and a document, no load, no popup menu and no dialog up, as above; the name (`not_found` naming `lib:name` when the body holds no symbol of that name). The `placeBody` cap is listed in a `sch` frame whose engine has `kicadPlaceImportedItem` and `kicadCollabGetSelection` (engine run 14 has both: no engine change).
