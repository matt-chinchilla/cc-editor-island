- `ev.boardItem { uuid: string, kind: string, isNew: boolean }` (island `v0.2.3-cc25`, cap `boardItemKinds`): in a `pcb` frame, KiCad was about to open its own window for a board item (E, a double click, the context menu's Properties) or for an item a tool just made, and held it for the host. `kind` is one of `pad`, `shape`, `dimension`, `textbox`, `barcode`, `image`, `zone` (a rule area, a keepout, a zone on no copper layer or a footprint's zone), `point`, `target`, `group`, `tuning`, `text` (`table` and `tablecell` are named too but the engine never asks for them on the board); `uuid` is the item's, the FIRST selected one's when several items of one kind are selected (one request for one E), `""` for the tuning tool's own settings (`tuning`, E or Ctrl+L while tuning) and for a picture about to be chosen (`image`, `isNew` true: nothing is placed and the tool ended; the host answers with `board.image.place`); `isNew` true for a new `text`, `textbox` or `barcode` (already placed as KiCad's dialog would place it with its defaults, a text reading "Text", one undo step) and a new `image`. Sent once per request, after `ev.ready`, while a board is open; never in place of `ev.boardProperties`, whose seven kinds and keys stand unchanged. Exactly these keys.

### Board item records, the tuning tool and pictures: board.item.get full, board.item.set records, board.tuning, board.image.place

Island `v0.2.3-cc25`, in a `pcb` frame, on engine run 15 (unit m4-i). A host gates each part on `ev.ready` `caps`: `boardItemKinds` (the engine has `kicadHostBoardItems`, `kicadBoardItemRecords`, `kicadBoardItemRecordsSet`, `kicadBoardItemGet` and `kicadCollabBusy`) for `full`, the record form and `ev.boardItem`; `boardTuning` (`kicadBoardTuningGet`, `kicadBoardTuningSet`) for the tuning ops; `boardImagePlace` (`kicadBoardPlaceImage`) for the picture. On an engine without them (run 14) none is listed, `board.tuning.*` and `board.image.place` answer `unsupported` naming the first missing export, `full` is ignored and the record form answers `unsupported` naming `kicadBoardItemRecordsSet`. In any other frame the new ops answer `unsupported` ("a board item op runs in a pcb frame").

- **`board.item.get` with `full: true`** (exactly `{ uuids, full: true }`): every uuid asked whose item is of a record kind answers its `BoardRecordSheet` (below) in place of today's `{ kind: "other" }` (a pad answers its own record, not its footprint); every other uuid answers as today, in the order asked. A record the island cannot read (one the closed readers of `bridge/itemRecords.ts` refuse) stays as today's answer, and a set on it answers `island_error`. `full` is honored only under `boardItemKinds`: an older host never sends it, so it never meets a kind its parser refuses.
- **`board.item.set`, the record form** (exactly `{ uuids, kind, set }`, beside today's `{ uuid, set }`): `uuids` 1 to 4,096 lower case, none twice, every one held (`not_found` names the first) and of `kind` (`bad_args`); `kind` a record kind but `tablecell` (the table's own commands); `set` a non empty partial of that kind's keys, only keys every item has: the footprint editor's item set for its kind (the `fpedit.items.set` section) plus, for a pad, `net` (a net the board holds, `""` for none; `bad_args` "the board has no net ..."); a group `name`, `locked`, `designBlock` (`"lib:name"` or `""`); a target `shape`, `size` (1 mil to 1,000 mm), `width`, `x`, `y`, `layer`; a tuning pattern every `TuningSettings` key but `mode` and `fromRules`. A kind the island reads no record of answers `unsupported`. ONE undo step "Edit" over every item, run in a fresh folder under `/tmp/cc-boarditems/` (the engine's record `items.json`, `{ run, applied, depth }`); KiCad's own rules refuse what its dialogs refuse (`bad_args`, nothing changed: the commit is reverted whole if any item refuses) and reset what they reset (a pad's shape as the pad dialog). The answer `{ items: BoardRecordSheet[] }` read back once it applied; past about 5 s `not_applied`. An `ev.edited` follows.
- **`board.tuning.get`**: the tuning tool's live settings while KiCad's track tuning tool runs, else `no_tuning`. Answered during a check (a read).
- **`board.tuning.set`**: exactly `{ set }`: amplitudes and spacing 0 to 1,000 mm, `cornerStyle`, `cornerRadiusPercent` a whole 0 to 100, the booleans, `target` replaced whole (`{ min?, opt?, max? }`, each 0 to 2,000 or null, `min` and `max` only beside an `opt`; mm, or ps while `timeDomain`; the other domain's target left unconstrained). Handed to the tool's own loop, which applies it as its dialog's OK applies it (the pattern being drawn is not committed: no undo step) and records the settings it then holds: the answer. `no_tuning` when no tuning tool runs or it ended before the set applied; `bad_args` when the engine refuses it.
- **`board.image.place`**: `name` a file name (no folder), `bytes` a PNG or a JPEG by its first bytes, at most 4 MiB. Staged under a fresh `/tmp/cc-stage/<n>/` (removed after the answer), then KiCad's own reference image tool runs with it, the file box skipped: `{}` once the picture hangs on the pointer on the active layer; the reader's press places it (KiCad's "Place Image", one undo step). `bad_args` when KiCad places nothing (another tool on its stack, a file it reads as no picture).
- **Held**: `pcbnew.LengthTuner.Settings` (Ctrl+L) in a `pcb` frame under `boardItemKinds`: `ev.held` with that action; the host opens its Tuning form on `board.tuning.get`.

The records (mm, degrees, positions the board's absolute ones, Y down; a string at most 1,024 characters unless named; any other shape is `island_error`):

- `BoardRecordSheet`: `{ kind: "record", uuid, parent, parentRef, net, netChoices, item }`. `parent` the footprint's uuid and `parentRef` its designator, both `""` for an item of the board itself; `net` a pad's net (`""` none), `null` for every other kind; `netChoices` every net of the board sorted for a pad, `[]` otherwise; `item` the item's own record, by its own `kind`.
- The footprint editor's kinds (`pad`, `shape`, `dimension`, `textbox`, `table`, `barcode`, `image`, `zone`: a rule area, a keepout or a zone on no copper layer, `point`): exactly the records of `fpedit.items.get`, but a pad's position is the board's and its `angle` relative to its footprint (as KiCad's pad dialog shows them).
- `group`: `{ kind: "group", uuid, name, locked, members, designBlock }` (`members` its item count, `designBlock` `"lib:name"` or `""`).
- `target`: `{ kind: "target", uuid, layer, x, y, shape: "plus" | "x", size, width }`.
- `tuning` (a placed pattern): `TuningSettings` plus `kind: "tuning"`, `uuid`, `layer`, as its dialog shows them (the rules' target while the pattern does not override them).
- `TuningSettings`: `{ mode: "single" | "diffPair" | "skew" (read only), minAmplitude, maxAmplitude, spacing, cornerStyle: "chamfer" | "round", cornerRadiusPercent, singleSided, timeDomain, overrideCustomRules, target: { min, opt, max }, fromRules: { min, opt, max } | null (read only) }`, each target number or null (all three null when unconstrained; the skew target in skew mode).
