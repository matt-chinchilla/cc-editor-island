### place.file
Puts a file the design holds on the pointer by KiCad's own Import Sheet (a `sch` frame, `kind: "sheet"`) or Append Board (a `pcb` frame, `kind: "board"`), with no file chooser and no window of KiCad's (island `v0.2.3-cc25`, on an engine with `kicadPlaceFromFile` and `kicadCollabGetSelection`, engine run 15; a host gates it on `ev.ready` `caps` listing `placeFile`, listed by a `sch` and a `pcb` frame on such an engine).

The host first writes the file into the project folder, under `imports/`, through `project.write`; `name` is that project path (relative, in its normal form: no empty, `.` or `..` segment, no backslash or control character, at most 1,024 bytes of UTF-8), ending `.kicad_sch` for a sheet and `.kicad_pcb` for a board. No bytes travel with the request. Any other key or shape answers `bad_args` "place.file", a kind of the other frame `bad_args` "place.file: a sheet places in a sch frame, a board in a pcb frame".

The checks, in order, before any effect: the args (`bad_args`); the frame (any frame but `sch` and `pcb` answers `unsupported` "a file places in a sch or pcb frame"); the engine (`not_ready`, `unsupported` naming the first missing export); a document open (`not_ready`); a load parked, a popup or a dialog up, or an item hanging off the pointer (`busy`); then the file: `not_found` (`message` the name) when the project folder holds none, `too_large` "place.file: <name> is over 25 MB". The frame copies the file to a fresh `/tmp/cc-stage/<n>/` (the engine reads only there, never the project folder), calls the engine with that path, and removes the folder after the answer, whatever it is.

The answer `{}` comes once the items hang off the pointer: a sheet's contents (always the contents: the island never turns KiCad's place as sheet option on, and a page wanting the file placed as a sheet uses `block.place` with `asSheet`), or the other board's items on KiCad's move tool (the destination keeps its stackup, page and title block). A click lands them as ONE commit, one undo step and an `ev.edited`; Esc leaves nothing and no undo step. The hanging placement is joined to `place`'s watch: every gate answers `busy` until it ends, and a later `place` cancels it first. `busy` "place.file: the editor cannot take a file now" when the engine refuses the call (an open in flight, a dialog up); `not_applied` when KiCad put nothing on the pointer within about 30 s (the file holds no items, or KiCad did not take it); `island_error` when the engine logged a refusal. A KiCad message about the file (a load error) reaches the host as KiCad's message ask, as every KiCad message box does on engine run 15.

KiCad's own Import Sheet and Append Board open nothing: under `placeFile` a `sch` frame holds `eeschema.InteractiveDrawing.importSheet` and a `pcb` frame holds `pcbnew.EditorControl.appendBoard`, each sending `ev.held { action }`; the host opens its own Import card. KiCad's drag and drop append (`pcbnew.Control.DdAppendBoard`) is left alone: no drop reaches KiCad's canvas.
