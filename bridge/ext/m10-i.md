### buses.migration.get
The buses whose labels give them two names, read in a `sch` frame with a schematic open (island `v0.2.3-cc25`, on an engine with `kicadBusMigrationGet`, engine run 15; a host gates it on `ev.ready` `caps` listing `busMigration`, listed by `sch` frames only). On this engine KiCad's own Migrate Buses window never opens when a schematic is opened: the labels stay as the file holds them until the host applies names. No args. The checks, in order: the args (`bad_args`); the frame (`unsupported` "a bus op runs in a sch frame"); the engine (`not_ready`, `unsupported` naming `kicadBusMigrationGet`); a schematic open (`not_ready`); a load parked, a popup or a dialog up, or an item hanging off the pointer (`busy`). A read: answered during a `sheet.check`. No event: a host asks once after each successful `project.open` or `project.import` in a `sch` frame when the cap is listed.

The answer lists at most 1,024 buses, each with KiCad's own id for it, the sheet path it lies on, its labels (1 to 64, each its `uuid`, lowercase, and its `text`) and KiCad's proposals, one per label, by KiCad's own rule. A proposal is not always the name a reader wants (KiCad may propose `DATA[0..0]` for `DATA[0..3]`): a host offers them, it never applies one unasked. An empty list means every bus has one name. An engine answer of another shape is `island_error`.

### buses.migration.apply
Names the buses in a `sch` frame with a schematic open (island `v0.2.3-cc25`, on an engine with `kicadBusMigrationApply` and `kicadCollabBusy`, engine run 15; cap `busMigration`). The args are exactly `{ choices }`: 1 to 1,024 choices of exactly `{ labels, name }`, the labels 1 to 64 uuids as `buses.migration.get` answered them (no uuid twice in one request), the name 1 to 1,024 UTF-8 bytes with no line break and no NUL. The checks, in order: the args (`bad_args`); the frame; the engine (`not_ready`, `unsupported` naming the first missing export); a schematic open (`not_ready`); `busy` as for `buses.migration.get`, and during a check or an import.

The frame queues the run with a fresh `/tmp/cc-buses/<n>/` for its records, waits for the apply queue to empty and the run's record, and removes the folder whatever the answer. Every label is resolved first: one the schematic does not hold as a label answers `bus_label_unknown` with nothing changed. Else each label takes its choice's name as ONE commit "Name buses" (one undo step, where KiCad's own window makes none), the connections are worked out again, and an `ev.edited` follows once the depth moved. The answer counts the choices applied and the labels named; a `buses.migration.get` after it lists none of those buses. `not_applied` when the engine refused the run or no record came within about 30 s; `island_error` for a record of another shape.
