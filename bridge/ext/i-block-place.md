### block.place

Island `v0.2.3-cc25`, in a `sch` or a `pcb` frame, on an engine with `kicadDesignBlockPlace`, `kicadCollabGetSelection` and `kicadCollabBusy` (engine run 15, units e-block-place and e-block-place-sch); a host gates it on `ev.ready` `caps` listing `blocks` (listed in a `sch` or `pcb` frame whose engine has `kicadDesignBlockPlace` and `kicadDesignBlockSave`). It places a design block the host keeps into the open design with KiCad's own placement and no KiCad window, no chooser and no pane: the block hangs off the pointer, a press puts it down as ONE undo step, Escape drops it with no step, as `place` does.

- `name`: the block's name, `block.save`'s rule (1 to 120 characters, none of `/`, `\`, `:` or a control character, never `.` or `..`).
- `files`: 1 to 3 of the block's own files, each `path` one of `<name>.kicad_sch`, `<name>.kicad_pcb`, `<name>.json`, none twice, `text` the file as KiCad wrote it; at most 32 MiB of UTF-8 together (`too_large` past it). A `sch` frame needs `<name>.kicad_sch` among them, a `pcb` frame `<name>.kicad_pcb` (`bad_args` "block.place: a block placed in a pcb frame needs <name>.kicad_pcb"). The island writes them under a fresh `/tmp/cc-block/<n>/<name>.kicad_block/`, outside the project folder.
- `asSheet`, `keepAnnotations`, `asGroup`: the three options of KiCad's own chooser, handed to KiCad as they are. In a `sch` frame `asSheet` true places the block's schematic as a new sheet: KiCad's smallest sheet box named after the block hangs off the pointer and the press puts the sheet down, its file `<name>.kicad_sch` (`<name>_2.kicad_sch` and on when taken) copied beside the project, which reaches the host with the next save's `ev.saved` like any sheet; false places the block's items. `keepAnnotations` keeps the block's designators; `asGroup` puts what is placed in one group named after the block.
- `nickname` (optional): the `design-block-lib-table` row the block came from (1 to 120 characters, no `:` or control character). With it a group placed as a group carries the block's link (`lib_id "<nickname>:<name>"`), so `block.applyLayout` and `block.save` `linkedGroup` work on it while that row is loaded (`project.libs`); without it the group carries no link. Send it only to an island listing `blocks`.
- One block at a time: an item of `place` or a block still hanging is dropped first (`busy` "the previous item still hangs off the pointer" when it would not go). The block's items, placed as contents, are watched as `place`'s item is, so every gate answers `busy` while they hang; a sheet's box is in no selection, so it is not watched by the other ops, and the next `block.place` drops it first.
- The checks, in order, every one before any effect: the args (`bad_args`, `message` the op); the size (`too_large`); the frame (`unsupported` "a design block is placed in a sch or pcb frame"); the frame's own file (`bad_args`); the engine (`not_ready` before it is up; `unsupported` naming the first missing export, so on engine run 14 `unsupported` "kicadDesignBlockPlace"); a document open (`not_ready`); a load parked, a popup menu or a dialog up (`busy`). Then `not_applied` "block.place: KiCad did not take the block" when the engine cannot read the block, `busy` "block.place: the editor did not take the block" when its items never reach the pointer within about 10 s (a sheet: when the engine's apply queue does not run within that time, `not_applied`), `island_error` for a throw.
- The run's folder under `/tmp/cc-block/` is removed once the items hang, and after every failure; a sheet's folder stays until the next `block.place`, since the press copies the sheet's file from it.
