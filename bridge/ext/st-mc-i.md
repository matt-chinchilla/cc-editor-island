### board.multichannel
KiCad's multichannel tool (Generate Placement Rule Areas and Repeat Layout) with no dialog, progress window or info bar, in a `pcb` frame with a board open (island `v0.2.3-cc25`, on an engine with `kicadMultichannel`, `kicadMultichannelApply` and `kicadCollabBusy`, engine run 15; a host gates it on `ev.ready` `caps` listing `multichannel`, listed by `pcb` frames only). The checks, in order, before any effect: the args, read closed (`bad_args`); the frame (`unsupported` "a multichannel op runs in a pcb frame"); the engine (`not_ready`, `unsupported` naming the first missing export); a board open (`not_ready`); a load parked, a popup or a dialog up, or an item hanging off the pointer (`busy`). The two reads are answered during a `board.check` or a `sheet.check`; `generate` and `repeat` then answer `busy`. During an import every op answers `busy`.

- `{ op: "areas" }` reads, with nothing changed: `areas`, every candidate KiCad finds for a rule area (`key` `sheet:<path>`, `class:<name>` or `group:<name>`, what `generate` takes; `name` the area's name KiCad gives it, `auto-placement-area-<source>`; `source` `sheet`, `componentClass` or `group`; `sheetPath` for a sheet, else ""; `parts` its part count; `exists` and `zone`, the uuid of a placement rule area holding exactly the same parts, else `false` and ""); `ruleAreas`, the board's placement rule areas (`zone` uuid, `name`, `source` as above or `designBlock`, `sourceName` KiCad's source text, `parts`); `canGenerate`, false where KiCad says it cannot make any (one or no candidate).
- `{ op: "check", ref }` (a rule area's zone uuid) answers KiCad's topology verdict for every OTHER placement rule area against it, with nothing changed: `zone`, `name`, `parts`, `matched` (the parts KiCad matched), `ok`, `message` ("OK" or KiCad's first reason) and `reasons` (KiCad's own mismatch lines). `not_found` (`message` the ref) when the ref is no rule area. The match runs to its end before the answer.
- `{ op: "generate", areas, replaceExisting, groupItems? }` (1 to 4,096 distinct keys from `areas`) makes a placement rule area for each, as KiCad's Generate Placement Rule Areas does past its dialog, the dialog's choices from the args: an area that exists is skipped unless `replaceExisting` (then removed first), `groupItems` groups each new area with its parts. ONE commit "Auto-generate placement rule areas" (one undo step), none when nothing was made. The answer `{ preview: false, areas, applied, depth }`: a row per key `{ key, name, parts, ok, reasons, skipped, zone? }` (`skipped` "", "exists" or "empty", a group with no board items; `zone` the new area's uuid when `ok`), `applied` the areas made, `depth` the undo depth after. `too_few` when KiCad cannot make any, `not_found` (`message` the key) for a key it does not find; nothing changed.
- `{ op: "repeat", ref, targets, options, preview }` (1 to 4,096 distinct zone uuids, not the ref) repeats the reference area's layout onto each target through KiCad's Repeat Layout, with KiCad's options (each absent one at KiCad's default; `anchor` a footprint uuid of the reference area, or ""). Group the items is not an option of a repeat (`bad_args`). A target that does not match is reported (`ok: false`, KiCad's reasons) and skipped, as KiCad skips it; the matching ones go in ONE commit "Repeat layout" (one undo step, and an `ev.edited` once the depth moved). `preview: true`, or a run where nothing matched, is reverted. The answer `{ preview, areas, applied, depth }`: a row per target `{ zone, name, parts, ok, reasons }`, `applied` the targets copied. `not_found` (`message` the uuid) for a ref, target or anchor the board does not hold, `copy_failed` when a copy failed (the whole commit reverted); nothing changed.

The apply's records are written under a fresh `/tmp/cc-multichannel/<n>/`, removed whatever the answer; `not_applied` when the engine refused the run or no record came within about 60 s; `island_error` for a record of another shape. KiCad's own Generate Placement Rule Areas (`pcbnew.Multichannel.generatePlacementRuleAreas`) and Repeat Layout (`pcbnew.Multichannel.repeatLayout`) are held in a `pcb` frame under the cap `multichannel`: each sends `ev.held { action }` and opens no window. The fixture is KiCad's own qa board `qa/data/pcbnew/issue21739/topology_mismatch` (read from the KiCad tree by path; `tests/e2e/st/st-mc-i.spec.ts`, engine run 15).
