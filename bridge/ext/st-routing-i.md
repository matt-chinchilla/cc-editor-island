### Routing: the sections `router` and `layerPairs`

Island `v0.2.3-cc25`, on an engine of run 15 or later. `settings.get` and `settings.set` take two more board sections in a `pcb` frame, KiCad's interactive router settings and its layer pairs with no KiCad window.

`router` reads KiCad's own router keys: `mode` (0 highlight collisions, 1 shove, 2 walk around; 2 on a fresh engine), `effort` (0 low, 1 medium, 2 full) and the switches `remove_loops`, `smart_pads`, `shove_vias`, `suggest_finish`, `follow_mouse`, `free_angle_mode`, `snap_to_tracks`, `snap_to_pads`, `optimize_dragged_track`, `auto_posture`, `fix_all_segments`; and the current sizes, in mm: `currentTrack { index, custom, width, customWidth }`, `currentVia { index, custom, diameter, drill, customDiameter, customDrill }`, `currentDiffPair { index, custom, width, gap, viaGap, customWidth, customGap, customViaGap }`. `index` points into the board's own list of sizes (0 is the net class value); `width`, `diameter`, `drill`, `gap` and `viaGap` are the sizes in use now and are read only; `custom` of the track and the via is one switch in KiCad, so a set of either reads back in both. A set's `value` names any of `mode`, `effort` (an integer 0 to 2), the switches (booleans) and the current objects, each with at least one of `index` (an integer from 0), `custom` (a boolean) and its own `custom*` sizes (0.001 to 100 mm); anything else, a read only size included, is `bad_args` before the engine is asked, and the engine answers `bad_args` for an `index` past the board's list. The engine applies an object's `index` first, then its sizes, then `custom`. The router's settings are the editor's, not the design's: a set makes no undo step and marks nothing modified, the live router takes it at once (a route in progress takes a new current size), and an engine boots with KiCad's defaults, so a host that keeps its reader's choices sends them again after each `ev.ready`.

`layerPairs` reads `{ pairs: [{ top, bottom, enabled, name }], current: { top, bottom } }`, layers by their file names (`F.Cu`, `In1.Cu`, `B.Cu`), `name` `""` for none. A set's `value` names `pairs`, `current` or both: `pairs` replaces the saved list whole (at most 256 rows, each `top` and `bottom`, an optional `enabled` defaulting to true and an optional `name` of at most 128 characters; KiCad drops a repeated pair), `current` sets the pair the router's layer switch uses. Each pair is two different copper layers by file name, else `bad_args` before the engine is asked; the engine answers `bad_args` for a layer the board does not enable. A set makes no undo step; KiCad keeps the saved pairs with the project.

A host gates each section on `ev.ready` `caps`: `settings:router` and `settings:layerPairs`, each listed in a `pcb` frame exactly when the engine's `kicadSettingsSections()` names the section in its board half (never on engine run 14). Both are board settings: a `sch` frame answers them `unsupported`.

Three of KiCad's router windows are held in a `pcb` frame while a document is open, each only while `ev.ready` listed the cap beside it: Interactive Router Settings (`pcbnew.InteractiveRouter.SettingsDialog`, its key `Ctrl+<`) and Differential Pair Dimensions (`pcbnew.InteractiveRouter.DiffPairDialog`) under `settings:router`, Set Layer Pair (`pcbnew.InteractiveRouter.SelectLayerPair`) under `settings:layerPairs`. The frame sends `ev.held { action }` and opens nothing (from a key, and on an engine whose menus ask the page, `heldMenus`, from KiCad's menus and toolbars); `action.run` of one answers `held`. The host opens its own routing settings instead.
