<!-- part: notes sim.netlist -->
- **A compiled model** (island `v0.2.3-cc25`). The simulator service is ngspice built for the browser: it loads no OSDI device, no XSPICE code model and no shared object. So the island reads the netlist and every file it includes that the frame's file system holds (each to at most 4 MiB, at most 64 files, a nested include read from its own file's folder) and lists one problem `{ code: "binary_model", severity: "error", ref?, path, text }` after KiCad's own for each line that names a compiled model: a line starting `pre_osdi` or `codemodel`, a `.model` of type `d_cosim` or an XSPICE instance (an `A` line) whose model, its last word, is `d_cosim`, or a `.model`, `.include`, `.inc` or `.lib` line naming a file ending `.osdi`, `.cm`, `.va`, `.vams`, `.so`, `.dll` or `.dylib`. Only those lines' words are read: a net or node name such as `/bus.va` is never taken for a file, and an instance's parameters load nothing. `path` is the compiled file the line names (relative to the project folder when inside it), else the file the line was read in; `ref` is the part's designator on an instance line; `text` is the line, continuations joined. `binary_model` joins the problem codes above for these answers only; KiCad's own problems never carry it.
<!-- part: notes sim.run -->
- **A compiled model refused before ngspice runs** (island `v0.2.3-cc25`). Before the run is queued the island reads the netlist with the run's options and scans it as `sim.netlist` does; any `binary_model` problem answers `circuit` with the first one's line as `message`, and nothing runs: no run is numbered and no `ev.sim` is sent. `sim.netlist` lists the problems. An FFT reruns no circuit and is not scanned. Measured on the island's `sim-binary` fixture (`tests/e2e/sim-binary.spec.ts`).
