### board.tuningSolve
KiCad's Tuning Profiles panel's work out for one layer row, with no KiCad window: the track width, the pair's gap or the delay KiCad's transmission line calculators give for a target impedance over the board's own stackup (island `v0.2.3-cc25`, on an engine with `kicadTuningSolve`, engine run 15, merged image only; a host gates it on `ev.ready` `caps` listing `tuningSolve`, a `pcb` frame only).

- The args are `type` (`single` or `differential`), `impedance` (ohms over 0, at most 1,000,000; a pair's differential impedance), `signalLayer` and the optional `topRef` and `bottomRef` (canonical copper layer names, `F.Cu`, `In1.Cu` to `In30.Cu`, `B.Cu`; a microstrip on `F.Cu` reads `bottomRef`, on `B.Cu` `topRef`, a stripline both), `solveFor` (`width`, `gap` or `delay`) and the optional `width` and `gap` in mm (over 0, at most 1,000). A gap, asked or given, is a pair's only.
- The answer is `{ width, gap, delay, problem }`: `width` and `gap` in mm, `delay` in ps/cm (KiCad's unit of the panel's Delay column) rounded to 4 places, each null when not worked out; `problem` is `""`, or KiCad's own message with every figure null when the row cannot be worked out ("Diff pair gap must be greater than 0 to calculate width").
- The checks, in order: the args (`bad_args`), then as for every board op (a `sch` frame answers `unsupported`; the engine with `kicadTuningSolve`, else `unsupported` naming it; a board open; `busy`). The engine answers `bad_args` for a layer the board does not enable or one that is no copper layer. A read: no record, no undo step, no `ev.edited`; answered during a check.

A host gates each on `ev.ready` `caps` listing `settings:<section>`, listed exactly when the engine's `kicadSettingsSections()` names the section in the frame's half; on any other engine a read answers `unsupported` naming `kicadSettingsSections` (run 14) or the section.

- The eight sections of engine run 15 (island `v0.2.3-cc25`; `settings.get` above names their keys) are set as patches, each value read closed before the engine is asked (`bad_args`: a key the section does not name, a value of another kind or out of KiCad's bounds, a null but a hatch offset's): `zoneDefaults` numbers, none negative but `hatch_orientation`; `zoneHatchOffsets` replaces the list, an enabled copper layer not named going back to the board default, each offset within 1,000 mm; `boardFormatting` ratios over 0 and at most 1,000; `tuningPatterns` merges each object, `corner_style` 0 or 1, `corner_radius_percentage` 0 to 100; `componentClasses` replaces `assignments`, each exactly `{ component_class, conditions_operator: "ALL" \| "ANY", conditions: { TYPE[-n]: { primary?, secondary? } } }`, TYPE one of `REFERENCE`, `FOOTPRINT`, `SIDE`, `ROTATION`, `FOOTPRINT_FIELD`, `CUSTOM`, `SHEET_NAME`; `tuningProfiles` replaces the list whole (names unique and not empty, type 0 or 1, a signal layer once per profile); `annotation` sort order 0 or 1, method 0 to 2, start 0 to 999,999 (the one key `schFormatting` also sets); `bomPresets` each value read by KiCad's own loader first and replacing its key whole. A `sch` frame's `componentClasses` set answers `unsupported` ("the schematic reads componentClasses and never sets it"): the board editor sets the classes. Then the engine as for a read (`unsupported` naming `kicadSettingsSections` or the section), then as for every set. Each set runs Board Setup's or Schematic Setup's own steps after it (the zone defaults loaded, the component classes and tuning profiles synchronized, the plot options and the painter's dash ratios set); no undo step, no `ev.edited`.
