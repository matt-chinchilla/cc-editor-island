### sch.rescue
Keep a copy of missing symbols: KiCad's Rescue Symbols with no window, in a `sch` frame with a schematic open (island `v0.2.3-cc25`, on an engine with `kicadSchRescue`, `kicadSchRescueApply` and `kicadCollabBusy`, engine run 15; a host gates it on `ev.ready` `caps` listing `rescue`, listed by `sch` frames only). The args are exactly `{ preview: true }` or exactly `{ names }`: 1 to 4,096 names, each 1 to 1,024 bytes of UTF-8 with no control character. The checks, in order, before any effect: the args (`bad_args`); the frame (`unsupported` "a rescue runs in a sch frame"); the engine (`not_ready`, `unsupported` naming the first missing export); a schematic open (`not_ready`); a load parked, a popup or a dialog up, or an item hanging off the pointer (`busy`). During a `sheet.check`, a `board.check` or an import it answers `busy`.

- `preview: true` lists the candidates and changes nothing: `RescueCandidate` is `{ name, libId, uses, rescuedAs }`, at most 4,096: `name` the symbol's name, `libId` the source the design names (`MyParts:R`), `uses` the placed symbols naming it, `rescuedAs` the source KiCad gives it once kept (`<stem>-rescue:R-MyParts`). A part is a candidate when the library its nickname names cannot be read and the design holds its own copy of the symbol (on a KiCad 6 or later design that copy stands in for KiCad 5's cache library), when that library's symbol has pins that disagree with the design's copy, or when its name holds characters KiCad no longer takes.
- `names` keeps a copy of the chosen candidates (a name matches a candidate's `libId`, or its `name` when no other candidate shares it): the design's copies are written into `<stem>-rescue.kicad_sym` in the project folder with its row in the project's `sym-lib-table` (type KiCad, `${KIPRJMOD}/<stem>-rescue.kicad_sym`), and every placed symbol naming them is relinked to the copy as ONE commit "Rescue Symbols": one undo step, and an `ev.edited` once the depth moved. The undo list is kept; an undo relinks the parts to their old source and the written files stay. Both files arrive as `ev.saved` before the answer; the answer is `rescued` (the candidates kept), `symbols` (the placed symbols relinked), `depth` (the undo depth after) and `saved` (the project paths sent as `ev.saved`).

`not_found` "a name matches no rescue candidate" when a name matches none (nothing changed, nothing written); `island_error` with KiCad's first line when the copies could not be written (the commit taken back); `not_applied` when the engine refused the run or no answer came within about 60 s. KiCad's own Rescue Symbols (`eeschema.EditorControl.rescueSymbols`) and Remap Legacy Library Symbols (`eeschema.EditorControl.remapSymbols`) are held in a `sch` frame under the cap `rescue`: each sends `ev.held { action }` and opens no window. The fixture `tests/fixtures/st-rescue-myparts/` (Glasgow with R4 and 11 more resistors drawn from `MyParts:R`, a table row the design does not carry) answers one candidate used 12 times (`tests/e2e/st/st-rescue-i.spec.ts`, engine run 15).
