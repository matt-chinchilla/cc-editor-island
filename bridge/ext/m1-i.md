### Our context menu (`contextMenu`)

Island `v0.2.3-cc25`. Our engine from run 15 (kicad `cc/main` K-MENU, in `TOOL_MANAGER::DispatchContextMenu`) asks the frame before it pops up any canvas menu of KiCad's, the clarify-selection list included, in every editor frame (`sch`, `pcb`, `symedit`, `fpedit`, `ds`). The frame takes the menu while `ev.ready` listed the pseudo-cap `contextMenu`, a document is open, no `project.import` runs and the host is connected; KiCad then waits, parked in the menu, and the frame sends `ev.contextMenu`. Otherwise KiCad's own popup shows as before and `ev.menu` reports it. `ev.ready` lists `contextMenu` exactly when the engine has `kicadHostContextMenu`, `kicadContextMenuChoose`, `kicadContextMenuHighlight` and `kicadRunAction`; on an older engine (run 14 and before) the cap is absent and every op below answers `unsupported` naming the export.

`ev.contextMenu`: `token` names the parked menu in every answer; `at` is the point KiCad asked for, in the frame document's CSS pixels; `title` is KiCad's (empty when it has none, "Clarify Selection" for the list); `kinds` are the distinct kinds of the selection, sorted (`board.item.get`'s words in a board or footprint frame; `symbol`, `field`, `pin`, `wire`, `bus`, `busentry`, `junction`, `noconnect`, `label`, `globallabel`, `hierlabel`, `directivelabel`, `sheet`, `sheetpin`, `text`, `textbox`, `table`, `tablecell`, `shape`, `image`, `group`, `rulearea`, `marker`, `other` in a schematic or symbol frame; `line`, `rect`, `text`, `image`, `other` in a drawing sheet frame). Each item of `items` is exactly `{ id: number, type: "action" | "choice" | "check" | "radio" | "submenu" | "separator", action: string, label: string, enabled: boolean, checked: boolean, key: string, door: "run" | "held" | "prompt" }`, a submenu adding `items`. `action` names KiCad's tool action (empty for a `choice`: a clarify candidate, a gate unit, a zoom or grid preset); `label` is KiCad's own text, with its accelerators, for the host to word (a clarify candidate's label is KiCad's description of the item, never reworded); `key` is KiCad's own key for the action, empty when none; `door` says where a choice ends: `run` (it runs, or the engine hands its form to the host, as for the properties forms), `held` (the island holds it in this frame: `ev.held` follows) or `prompt` (its window is an `ev.prompt` card). An action whose window has no door of ours in this frame (the doors table `bridge/ext/contextMenuDoors.json`, or a held row whose cap is not listed, or a prompt with no `prompts` cap) is left out, never grayed, and named in `omitted`; a submenu left empty goes too, and separators are collapsed (none first, last or doubled). The engine bounds a menu at 400 items, three levels and 128 characters a label. The list may be empty: the host then answers `contextMenu.choose { id: -1 }`.

`contextMenu.choose { token, id }` resolves the parked menu with the item `id`, which KiCad then runs as its own popup would (a check item toggles, a held action sends `ev.held`); `id` `-1` closes it with nothing chosen. Every close of the host's menu sends one choose: a choice, or `-1` for a close with none. A choice is followed by a read of the selection, as a pointer release in the frame is: an item that changes it inside the engine (Select the rest of its sheet) raises no canvas event, and `ev.selected` follows when it changed. It answers `{}`, or `stale` (no menu parked with that token; the host closes its menu), `no_item` (an id the menu was not sent with, an omitted action, a submenu or a separator), `disabled`, `bad_args`. `contextMenu.highlight { token, id }` tells KiCad the item under the host's pointer or focus: in a clarify list KiCad brightens that candidate on the drawing, as on the desktop. Same answers, `-1` refused. Both are answered as they arrive, outside the one-at-a-time order (KiCad is parked in the menu, so a queued request would wait on it forever); no `ev.contextMenuEnd` follows a choose.

While a menu is parked the frame counts it as a popup over the canvas: `key.press` and `view.fit` answer `busy`, a schematic's `project.save` closes it first (as Escape, `ev.contextMenuEnd` `canceled`) and then saves, and a press or Escape in the frame closes it. The ContextMenu key and Shift+F10 in the frame, with nothing over the canvas and no text field focused, run `common.Control.showContextMenu` (KiCad's keyboard menu at its own cursor).

`action.run { name }` runs one tool action of KiCad's by its name (`pcbnew.InteractiveEdit.moveExact`), as a press of its menu item would, on the request queue like `key.press`. It answers `{}`, or `bad_args` (not an action name), `held` (the island holds it in this frame: nothing ran, the host opens its own door), `unsupported` (no `kicadRunAction`, or the action opens a window of KiCad's that has no door in this frame: nothing ran), `not_ready` (no document open), `busy` (a load is parked, a menu, a prompt or a dialog is up, or a placed item hangs off the pointer), `unknown_action` (no tool action of that name in this frame).
