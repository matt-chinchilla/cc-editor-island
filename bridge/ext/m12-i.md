### Tables (`tableCsv`)

Island `v0.2.3-cc25`, in a `sch` or a `pcb` frame. Our engine from run 15 (unit m12-e) asks the host in place of KiCad's Table Properties and Table Cell Properties windows, through the prompt host (Prompts, above), and builds a table's CSV with no window.

The table asks and their records (lengths in millimeters, colors `#rrggbbaa` lowercase or `""` for none, a stroke's `style` `solid`, `dash`, `dot`, `dashdot` or `dashdotdot`):

- `table` (Edit Table, `Ctrl+E` on a table, and a cell's own Edit Table press): `{ uuid, rows, cols, cells, border: { external, header, width, color, style }, separators: { rows, cols, width, color, style }, layer, locked }`. `cells` is the grid's text row by row, `rows` arrays of `cols` entries, a cell covered by a merged one `null`; a board table on a back layer arrives mirrored, as KiCad's grid shows it. A `width` is `null` when the stroke has none. `color` is always `""` on the board (its dialog has no colors); `layer` is the board's canonical layer name, `""` in a schematic; `locked` is always false in a schematic. Answer `{ cells, border, separators, layer, locked }`, any key left out or `null` keeps its value (a stroke block may carry only the keys it changes); KiCad refuses with the key it names (`cells`, `border.width`, `separators.style`, `layer`, `locked`) a cells array not `rows` by `cols`, a negative width, a color other than `""`, `#rrggbb` or `#rrggbbaa`, a style not in the list, a board color other than `""`, a schematic `layer` other than `""` or `locked` true, a board layer its selector does not offer. One accepted answer is one undo step.
- `tableCell` (Properties of one or more selected cells): `{ uuids, text, font, bold, italic, hAlign, vAlign, margins: { left, right, top, bottom }, size, width, height, thickness, autoThickness, textColor, fill: { mode, color } }`, every key always present. A value is `null` where the selected cells differ (KiCad's mixed state) or where it does not apply in this editor: `size`, `textColor` and `fill` are the schematic's, `width`, `height`, `thickness` and `autoThickness` the board's. `text` is `null` for several schematic cells. `font` is the font's name (`KiCad Font` or a system font), `hAlign` `left`, `center` or `right`, `vAlign` `top`, `center` or `bottom`, `fill.mode` `none` or `color`. Answer the same keys but `uuids`, each optional (`null` or left out keeps the value; a non null value for a key that does not apply in this editor is refused with that key), plus `editTable`: `true` is the dialog's own Edit Table press, after which KiCad asks `table` for the cell's table as a second, separate prompt. Each accepted answer is one undo step.

`table.csv { uuid }` answers `{ name, text }`: `text` the table's text as KiCad's own Export Table to CSV writes it (each cell's shown text, a field holding a comma, quote or line break quoted with its quotes doubled, fields joined by `,`, each row ended by a line break), `name` the project's name followed by `-table` (`table` when the project has none); the host saves it as `<name>.csv`. A read: nothing changes and no undo step is made, and it is answered during a `sheet.check` or `board.check`. Failures: `bad_args` (any key but `uuid`, or a `uuid` that is not one), `unsupported` (in another frame, or on an engine without `kicadTableCsv`, named), `not_ready` (no document open), `busy` (a load parked, a popup menu, a dialog or a prompt up, or a placed item on the pointer), `not_found` (no table of the document holds the uuid; `message` the uuid).

`ev.ready` lists `tableCsv` in a `sch` or `pcb` frame exactly when the engine has `kicadTableCsv`. While it is listed, KiCad's Export Table to CSV (`common.TableEditor.exportTableCSV`, which would open a file window) is held in both frames: its window never opens, the frame sends `ev.held`, and the host asks `table.csv` for the selected table and saves the file itself. On an older engine (run 14 and before) the cap is absent, the action keeps no door in our menu, and `table.csv` answers `unsupported` naming `kicadTableCsv`.
