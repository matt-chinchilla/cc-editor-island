### sim.userSignals

The reader's own signals over an ended run: KiCad's user defined signals (its simulator's `applyUserDefinedSignals`), worked out by ngspice with no KiCad window (island `v0.2.3-cc25`, on an engine with `kicadSimUserSignals`, engine run 15; a host gates it on `ev.ready` `caps` listing `simUserSignals`, listed in a `sch` frame exactly when the engine has that export).

- **The args**, read closed: `run` (a run number `sim.run` answered) and `signals`, 0 to 16 expressions, each 1 to 256 printable ASCII characters with no line break or other control character, no `;`, no quote (`"` or `'`), no backslash, no backtick and no brace. A `let` takes one expression, so nothing that passes can become a second command; anything else answers `bad_args` and nothing reaches the engine or ngspice. Name nets as KiCad's circuit names them, with the sheet path: `V(/out)-V(/in)`, `V(/out)*I(R1)`.
- **The checks**, in order: the args (`bad_args`); the frame (`unsupported`, "the simulator runs in a sch frame"); the engine (`not_ready` before `ev.ready`, `unsupported` naming `kicadSimUserSignals` or `kicadCollabBusy` when absent, as on engine run 14), a schematic open (`not_ready`), a load parked, a popup menu or a dialog up, or an item hanging off the pointer (`busy`); the simulator service (`unsupported` "ngspice_service.wasm" when the release serves none); `busy` while a run is live; `no_simulation` when the service was released or died since the run.
- **The run's plot.** The island asks the service for its plots and hands the engine each in turn; the engine takes only a plot the run's finish recorded and the service still holds (and queues nothing for any other), so the island never sends a plot of its own guess. When none is taken the run is no longer held (a newer run of its kind replaced it, or it made no plot) and the answer is `no_simulation`, as `sim.vectors` answers.
- **The work.** In a fresh folder under `/tmp/cc-sim/`, the engine makes ngspice's plot current and, for each signal `i`, clears `user<i>` and sends `let user<i> = <expression>` with the circuit's net names quoted by KiCad's own rule; its record `user-signals.json` is read once the engine is idle (`not_applied` past about 30 s) and the folder is removed. No undo step; the design is not marked modified.
- **The answer**: `vectors`, one `SimVector` per expression ngspice worked out, `name` `user<i>` (`i` its index in `signals`), `signal` the expression as sent, `trace` `other`, `complex` and `length` as ngspice holds it; `errors`, `{ index, line }` for each expression ngspice refused, `line` ngspice's first error line for it, else "ngspice made no vector for this expression" or "ngspice refused the expression". `no_simulation` when the engine found the plot gone at its turn; `sim_failed` with the engine's message when ngspice could not be asked.
<!-- part: notes sim.vectors -->
- `sim.vectors` also reads the vectors `sim.userSignals` made for that run (`user0` to `user15`, the names its answer gave, from the plot they were made in), mixed in any order with the run's own names; a `user<i>` the latest `sim.userSignals` of that run did not make answers `bad_args` as any other unknown name, and one whose plot is gone `no_simulation` (island `v0.2.3-cc25`).
