### The 3D service

KiCad's 3D exports other than VRML (STEP, STEPZ, BREP, XAO, GLB, PLY, STL, U3D, PDF) and its reading of a part's STEP or IGES body run on OpenCASCADE, which the editor's wasm does not carry. The island serves it as a program of its own, `occ_service.wasm` with its script `occ_service.js`, beside the engine files, and runs it in a worker of the `pcb` frame (island `v0.2.3-cc25`, on engine run 15).

- **Cap `occ`**: listed in `ev.ready` `caps` of a `pcb` frame when this island id serves both service files (PIN.json records them, and the build serves both or neither) and the frame installed the service as `globalThis.occService`. Never listed in a `sch` frame. Without `occ` a host keeps the 3D rows other than VRML held.
- **Lazy**: installing the service fetches nothing. The first export or STEP body the engine asks for fetches the wasm (the browser's compiled code cache is used), compiles it and boots the worker; later requests reuse it.
- **Exports**: the engine's request carries the absolute path it reads the file back from; the service gathers the parts' bodies through the island's staging (each body by its path relative to the model root, `kiprjmod/<relative path>` or `<Lib>.3dshapes/<Name>.<ext>`: the service stages no other path), runs the export in the worker and writes the bytes at that path in the engine's file system. Nothing is handed to the browser. A request that names no path is answered "The 3D service was given no file to write."; one that gives no bytes, "The 3D service made no file." (engine run 15 also fails an answer that leaves no file or an empty one with that line).
- **Report**: the answer's `report` is the one road KiCad's exporter's lines take ("Could not add 3D model for R1. File not found: ..."), joined with the staging's own line. The engine reports it as one error line when the export failed (it then reads in `export_failed`'s message) and as one info line when it succeeded, which `project.export`'s `notes` do not carry on engine run 15.
- **Release**: the worker is ended 60 s after its last answer, and at once when the bridge closes; the next request boots a new one.
- **Death**: a worker that ends with requests waiting (a fault, or a worker that closed itself) answers every one `{ ok: false, report: "The 3D service stopped." }`, which the engine reports as the export's failure (`export_failed` through `project.export`); the next request boots a new worker.
