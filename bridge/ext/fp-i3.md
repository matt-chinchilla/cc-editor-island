### The footprint's properties, its embedded files, the checker, Tidy and the SVG

Island `v0.2.3-cc25`, in an `fpedit` frame with a footprint open, on an engine with the fpedit exports (engine run 15: `kicadFpEditFootprintGet`, `kicadFpEditFootprintSet`, `kicadFpEditEmbed`, `kicadFpEditCheck`, `kicadFpEditCleanup`, `kicadFpEditPlotSvg`); a host gates every op on `ev.ready` `caps` listing `fpedit`. The checks are the fpedit ops' own, in their order (the args, `unsupported` outside an `fpedit` frame, `not_ready`, `unsupported` naming the first missing export, `busy`, `no_footprint`). `fpedit.footprint.get` and `fpedit.check` are reads and answer during a check.

- `FootprintProps` is exactly `{ name, description, keywords, fields, type, boardOnly, excludeFromPos, excludeFromBom, dnp, allowMissingCourtyard, allowSolderMaskBridges, clearance, maskMargin, pasteMargin, pasteRatio, zoneConnection, netTieGroups, jumpers, privateLayers, customStackup, userLayerNames, models, embedded }`, as KiCad's footprint properties dialog shows them. `fields` in the footprint's order, each `{ name, value, visible, layer, kind }`, `name` the canonical one (Reference, Value, Datasheet, Description, then the user's), `kind` `reference`, `value`, `datasheet`, `description` or `user`. `type` `smd`, `through_hole` or `unspecified`. `clearance`, `maskMargin` and `pasteMargin` in mm, null for the board's; `pasteRatio` KiCad's own fraction from -1 to 1 (the dialog shows it as a percent), null for the board's; `zoneConnection` `inherit`, `none`, `thermal` or `solid`. `netTieGroups` the pad lists KiCad stores (no empty one); `jumpers` `{ duplicateNumbersAreJumpers, groups }`, each group pad numbers. `privateLayers` canonical layer names. `customStackup` `{ on, copperLayers }` (`copperLayers` reads 2 unless `on`). `userLayerNames` the user layers the editor enables, canonical name to shown name: the editor's preferences, not the footprint's. `models` at most 32 lines `{ path, offset, rotate, scale, opacity, show }` (offset in mm, rotate in degrees, each three numbers). `embedded` `{ name, type, bytes }` per embedded file, `bytes` its size before KiCad compresses it, `type` `model`, `datasheet`, `font` or `other`. Strings are at most 1,024 characters, but the description, the keywords and a field's value, read up to 16,384.
- **`fpedit.footprint.set { set }`**: `FootprintSet` is any of FootprintProps' keys but `fields` and `embedded`, at least one, plus `fields` (patches by name, `{ name, value?, visible?, layer? }`, none twice), `addField` (`{ name, value, visible, layer }`, a new user field) and `removeField` (a name). The island checks the shape and KiCad's bounds (clearance 0 to 100 mm, margins -100 to 100 mm, `pasteRatio` -1 to 1, a custom stackup of an even 2 to 32 copper layers, at most 32 models with rotation within 360 degrees, scale 0.0001 to 10,000, offset within 1,000 mm and opacity 0 to 1, texts of at most 1,024 characters, a line break only in the description); `userLayerNames` is read only, taken only when it equals the get's (`bad_args` "fpedit.footprint.set: userLayerNames is the editor's and read only" otherwise). The engine refuses (`bad_args` "fpedit.footprint.set", nothing changed) a mandatory field added or removed, a jumper group naming a pad the footprint lacks, a private copper, technical, Edge.Cuts or Margin layer, a custom stackup that orphans a layer in use, or a name KiCad's library names refuse. `models` replaces the list; a `name` renames the footprint in the editor only (the host renames the file on save). The setters run in the dialog's order as ONE commit "Footprint properties": one undo step and an `ev.edited`. The answer is the properties read back once they show every key given, or the undo step (KiCad's rules may change a value given), else `not_applied` after about 5 s.
- **`fpedit.embed`**: `{ name, type, bytes }` (a name of 1 to 255 characters with no slash or backslash, never `.` or `..`; the file's bytes, a `Uint8Array` of 1 byte to 25 MiB) is written under a fresh `/tmp/cc-embed/<n>/` outside the project folder and embedded in the footprint by KiCad's own embedded files (compressed and hashed; a file of that name is replaced), ONE commit "Embed a file"; `{ remove }` takes one out, ONE commit "Remove an embedded file" (`not_found`, the name, when the footprint embeds none of that name). The answer is the properties once `embedded` shows the change (a new file with its type and size), the folder removed; `bad_args` "fpedit.embed: KiCad refused the file" when the engine refuses it, `not_applied` after about 5 s. `fpedit.take` carries the embedded files.
- **`fpedit.check`** runs KiCad's footprint checker (`DIALOG_FOOTPRINT_CHECKER::runChecks`, in its order, collecting in place of markers): `{ findings }`, each exactly `{ code, severity, message, uuids, pads, x, y }`. `code` is KiCad's settings key: on engine run 15 `malformed_courtyard`, `missing_courtyard`, `footprint_type_mismatch`, `padstack`, `padstack_invalid`, `through_hole_pad_without_hole`, `holes_co_located`, `hole_to_hole`, `shorting_items`, `footprint` and `silk_over_copper` (a host words these and shows `message`, KiCad's own sentence, for any other); `severity` `error` or `warning` by the design settings (an ignored code is left out); `uuids` and `pads` the items and pad numbers concerned (at most three); `x`, `y` the point in mm in the footprint's frame, both null for a finding on the footprint itself. Nothing changes.
- **`fpedit.cleanup`** is KiCad's Cleanup Graphics over the footprint's drawings (the dialog's 2 mm tolerance) and, with `repair`, Repair Footprint (KiCad 10 renews duplicate uuids). The answer `{ items, repaired }` is what a dry run finds: `items` `{ code, uuids }`, `code` `null_graphic`, `duplicate_graphic`, `lines_to_rect`, `merge_pad` (or `other`), `repaired` the duplicate uuids. With `dryRun` nothing changes; without it the same runs as ONE commit "Tidy footprint" and the answer comes once that undo step shows (`not_applied` after about 5 s), none when nothing is found.
- **`fpedit.svg`** plots the footprint's layers the view shows with KiCad's own SVG plotter (no frame, the page fitted to the footprint, no mirror) into a fresh `/tmp/cc-svg/<n>/`, its record `.cc-svg.json` written last; the answer is the file's bytes (a fresh `Uint8Array`, transferred, at most 4 MiB), the folder removed. `plot_failed` when KiCad wrote no SVG; `not_applied` when no record came within about 30 s.
