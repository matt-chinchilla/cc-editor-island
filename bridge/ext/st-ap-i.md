- `ev.autoplace { working: boolean }`: in a `pcb` frame (island `v0.2.3-cc25`, cap `autoplace`), KiCad's auto-placer is working (`true`) or done (`false`). Sent around a `key.press` of the chord `theme/user.hotkeys` seeds for Place Off-Board Footprints (`pcbnew.Autoplacer.autoplaceOffboard`, `Ctrl+Alt+L`) or Place Selected Footprints (`pcbnew.Autoplacer.autoplaceSelected`, `Ctrl+Alt+P`): `working: true` before the key reaches KiCad, `working: false` once the run is over, read every 250 ms after the press (the engine's apply queue empty and the undo depth moved, or about 1 s with nothing changed: no part to place, or a board with no outline, which KiCad answers on its own info bar). A press the frame refuses (`busy`: a menu or a dialog of KiCad's is up) sends `working: false` right after the `true`. A second chord pressed while a run is watched joins it (one `true`, one `false`). A run is one undo step ("Autoplace Footprints"), then an `ev.edited`; the auto-placer cannot be stopped midway. The cap `autoplace` is listed in a `pcb` frame exactly when the engine has the marker `kicadAutoplaceQuiet` (engine run 15: the auto-placer runs with no progress window of KiCad's) and `kicadCollabBusy`; without it (engine run 14 and older) the press opens KiCad's progress window and no `ev.autoplace` is sent. A key the reader types inside the frame sends none.
